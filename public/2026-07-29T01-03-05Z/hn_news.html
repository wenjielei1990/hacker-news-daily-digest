Codex Security HN 讨论 · 86

OpenAI 推出了 Codex Security，这是一个用于发现、验证和修复代码安全漏洞的工具。它提供 CLI 和 TypeScript SDK，支持在本地开发环境或 CI/CD 流水线中扫描代码库。该工具的核心机制是利用大语言模型结合特定的“技能”定义来识别复杂的漏洞模式。虽然它能提供自动化的修复建议，但早期用户反映其扫描速度较慢且会消耗大量 API 额度。此外，将源代码上传至云端进行分析也引发了企业对隐私和合规性的担忧。

展开详情 ↓

OpenAI 发布的 Codex Security 旨在通过大语言模型（LLM）的力量，将安全审计从单纯的检测扩展到自动修复。该工具以 Node.js CLI 和 TypeScript SDK 的形式提供，要求环境具备 Node.js 22 和 Python 3.10 以上版本。其技术核心在于一套名为“技能”（Skills）的定义，这些本质上是经过精心优化的自然语言提示词，指导模型如何识别特定的安全威胁并验证其有效性。开发者可以通过简单的指令对整个仓库或增量更改进行扫描，并能直接在 CI 环境中集成安全检查。

然而，在实际应用中，该工具面临着显著的性能和成本权衡。根据早期用户的反馈，即使是小型代码库，扫描过程也可能持续近一小时，并迅速耗尽 ChatGPT Pro 的周使用配额或产生高额 API 费用。此外，由于代码必须上传到 OpenAI 的服务器进行处理，这对于有严格隐私政策或代码不出境要求的企业构成了挑战。目前该项目仍处于早期阶段，OpenAI 团队正在积极寻求社区反馈，并计划在并发处理、扫描进度展示以及认证流程上进行改进。未来值得关注的是，这种基于语义理解的扫描方式是否能比传统的静态分析工具（SAST）提供更低的误报率。

Kimi K3 是月之暗面（Moonshot AI）最新发布的超大规模开源权重模型，其参数量达到了惊人的 2.8 万亿。该架构在 Kimi Linear 的基础上进行了大幅扩展，核心创新在于引入了 LatentMoE 和 Kimi Delta Attention (KDA) 以显著提升推理效率。最引人注目的技术突破是它彻底舍弃了旋转位置编码（RoPE），转而全面采用无位置编码（NoPE）方案。这种设计之所以可行，是因为其混合架构中的 KDA 层具有类似循环神经网络（RNN）的特性，能隐式捕捉序列位置信息。作为目前最大的开源模型之一，K3 在多模态支持和实际应用表现上已展现出挑战顶级闭源模型的实力。

Kimi K3 代表了开源模型规模的新巅峰，其 2.8T 的参数量远超此前的版本。为了在如此庞大的规模下保持推理效率，架构大量采用了优化组件：LatentMoE 通过下采样压缩大型线性层，而多头潜在注意力（MLA）则进一步降低了显存占用。此外，K3 引入了“注意力残差”机制，通过注意力分数对跨层残差进行加权连接，这种设计虽然让训练和推理成本分别增加了 4% 和 2%，但换来了更优的验证损失和下游任务表现。

在位置编码方面，K3 采取了激进的 NoPE（无位置编码）策略，这在当前主流模型中非常罕见。通常模型依赖 RoPE 来识别 Token 顺序，但 K3 利用其特有的 Kimi Delta Attention (KDA) 层解决了这一问题。KDA 本质上是一种可并行化的循环神经网络（RNN）变体，其隐藏状态充当了可编辑的记忆单元，天然具备处理序列顺序的能力。这种混合架构使得全局注意力层无需显式位置信息也能理解上下文，从而避免了 RoPE 可能带来的某些负面影响。尽管技术文档详尽，但这种复杂架构在实际部署中也带来了挑战，例如 KV 缓存必须以固定块进行增量更新，可能导致缓存未命中时的额外计算。然而，初步测试显示 K3 的性能已能与 Claude 4.7 等顶级闭源模型并驾齐驱。

Zig's Incremental Compilation Internals HN 讨论 · 133

Zig 编译器通过引入增量编译机制，实现了在复杂应用中仅需几十毫秒即可完成代码重建。该系统将编译过程拆分为细粒度的“分析单元”，并利用依赖图追踪源码变动对类型、函数体等具体部分的影响。其核心突破在于深度集成的增量链接器，它能直接在内存映射的二进制文件中“打补丁”，动态调整函数空间而无需重新链接整个程序。为了实现这种极致性能，Zig 在语言设计上做出了多次调整，以确保依赖关系可被静态追踪。目前该功能在开发分支中已趋于成熟，预计将在 0.17.0 版本中正式面向稳定版用户开放。

展开详情 ↓

Zig 核心团队成员详细介绍了该语言实现毫秒级增量编译的内部机制。编译流程首先将源文件转换为中间表示（ZIR），这一步是高度并行的且带有缓存。核心挑战在于语义分析阶段，Zig 将其拆分为布局、类型、值和函数体四种“分析单元”。通过建立这些单元与源码哈希之间的依赖图，编译器能精确识别出哪些函数需要重新分析，从而避免了传统编译器中常见的冗余计算。这种设计甚至反向影响了 Zig 的语言规范，为了便于追踪依赖，语言在设计上做出了一些权衡。

在后端，Zig 采用了与众不同的集成链接策略。传统的外部链接器通常需要重新读取所有目标文件，而 Zig 的增量链接器通过 `MappedFile` 抽象直接操作输出的二进制文件。它将文件视为一棵可动态调整大小的节点树，当某个函数代码变长时，链接器会自动移动周围的节点并更新重定位信息，实现原地“打补丁”。这种紧密集成规避了传统工具链中跨进程通信和重复解析的开销。虽然目前该功能主要针对调试构建（Debug builds），但它展示了通过协同设计语言与工具链所能达到的性能极限。

The Difference Between a Button and a Link HN 讨论 · 3

本文探讨了 HTML 中按钮（Button）与链接（Link）的本质区别：链接代表“目的地”，允许用户在不同上下文中开启（如新标签页、书签）；而按钮代表“动作”，通常在当前上下文中执行。目前 HTML 的局限在于，按钮若不包裹在表单中，就无法原生触发导航或网络请求。为此，作者提出了“Button Actions”提案，建议为按钮标签增加 action 和 method 属性。这一改动能避免开发者为了实现简单跳转而将链接伪装成按钮，从而解决语义混淆和无障碍体验不佳的问题。该提案旨在让 HTML 原生支持更完整的 CRUD 操作，减少对 JavaScript 的依赖。

展开详情 ↓

作者指出，Web 用户直觉上能区分按钮和链接，但开发者在实现时常感到困惑。链接的核心在于其“可重构性”，浏览器为其提供了右键菜单、中键点击和书签等丰富功能，因为链接指向的是一个独立的资源。相比之下，按钮执行的是特定环境下的动作，如“保存”或“删除”，这些动作不应具备“在新标签页打开”等链接特有的属性。目前的 HTML 标准迫使开发者在处理非表单动作（如“取消”跳转）时，要么使用复杂的 JavaScript，要么使用 CSS 将链接伪装成按钮。

这种“伪装”被视为一种反模式，因为它向用户提供了错误的交互预期，且在阅读模式或无障碍设备中表现不一。提案建议允许按钮直接定义请求目标和方法（如 GET 或 DELETE），从而在不依赖脚本的情况下实现语义化的状态转换。这一提议属于更广泛的 Triptych 项目，目标是让 HTML 具备类似 HTMX 的能力，原生支持完整的增删改查（CRUD）生命周期。虽然目前仍需解决 XSS 安全性分析等挑战，但该方向得到了 Django 软件基金会等组织的支持。如果被采纳，它将显著降低 Web 开发的复杂度，并提升政府网站等强调“渐进增强”场景的开发效率。

Deltafin 是一个开源研究项目，旨在挑战在个人电脑上运行前沿规模大模型的极限。它成功让拥有 2.8 万亿参数的 Kimi K3 模型在配备 64GB 内存的 M1 Max Mac 上跑了起来。由于模型总重达 1.56TB，远超内存容量，Deltafin 采用了“硬盘流式推理”策略：将 114GB 的常驻骨干权重（包含注意力机制和共享专家）量化为 int8 并存放在 NVMe 硬盘中，每生成一个 token 都会重新读取；而 1.45TB 的路由专家权重则以 MXFP4 格式存储，仅在推理选中时才从硬盘或通过网络（Hugging Face）加载。

为了尽可能压榨性能，该项目引入了多项优化技术，包括针对 Apple Silicon 优化的融合 MXFP4 解码内核、Metal GPU 加速、双缓冲层加载以及 n-gram 投机采样。在 M1 Max 上的实测显示，本地模式下生成速度约为每 token 15-16 秒，而网络流式模式则需 3 分钟以上。目前的性能瓶颈完全在于硬盘带宽，因为每一步推理都需要从 SSD 吞吐数十 GB 的数据。这种“以空间换时间”的方案虽然目前还无法用于实时聊天，但为离线知识检索和异步 AI 任务提供了一种可能性。未来随着 M4/M5 Max 等拥有更高内存带宽和更大内存容量的设备普及，这种本地推理的实用性有望大幅提升。

Kimi Linear 的设计初衷是解决标准 Transformer 随序列长度增加而产生的计算开销激增问题。它引入了 Kimi Delta Attention (KDA)，这是对 Gated DeltaNet 的重要改进，通过引入细粒度门控，让模型能像 RNN 一样在有限的状态空间内存储更多有效信息。为了让这种架构在现代 GPU 上跑得更快，研究团队开发了一种基于对角加低秩（DPLR）矩阵的块状算法，这在保证数学一致性的同时，大幅优化了计算效率。这种设计使得模型在保持线性复杂度的同时，拥有了媲美甚至超越全注意力机制的表达能力。

在实际部署中，Kimi Linear 采用了 KDA 与多头潜在注意力（MLA）的层级混合设计。实验模型包含 30 亿激活参数，总参数量达 480 亿。测试结果显示，在处理 100 万 token 的超长文本时，该架构的解码速度是传统模型的 6 倍，且 KV 缓存需求仅为后者的四分之一。这意味着在相同的硬件资源下，Kimi Linear 可以支持更长的对话上下文和更高的并发量。目前，该项目已开源了 vLLM 实现和预训练权重，这不仅展示了线性注意力架构的潜力，也为未来超长上下文 AI 的普及提供了技术路径。未来值得关注的是，这种混合架构在更大规模参数（如千亿级）下的表现是否依然稳健。

我的专业领域是深度学习理论。是的，这种“智能”主要源于规模化（scaling）等因素。这背后有充分的理由，但本质上可以归结为利用了一种狭窄的统计技巧：一个精心设计的模型/优化器组合，如果对“简单性”有强烈的隐式偏置，就能随着模型规模的增大表现出持续提升的性能。Marcus Hutter 的实验室已经证明，这可以用所罗门诺夫归纳法（Solomonoff induction）来表述，因此这种偏置确实是普遍有效的。一种有效的偏置可以通过利用维度诅咒，以类似于“更多数据通常能给你更好答案”的方式，在更大的模型规模下持续改进性能（实际上这里存在一种对偶性，但我扯远了）。需要明确的是，只有极少数模型类别能做到这一点；我们只是“运气好”摸索到了它。这就是为什么我们仍然教授通用的统计原则，而这些原则通常将这种行为视为禁忌。

LLM 锐评

线性注意力（Linear Attention）长期以来被视为 Transformer 的“圣杯”，因为它能将计算复杂度从平方级降至线性级，但往往以牺牲模型表达能力为代价。Kimi Linear 的出现标志着这一领域的重要突破，它不仅在效率上占优，更在多个基准测试中正面击败了全注意力架构。这种“既要又要”的进步，配合 Kimi 团队在长文本领域的深耕，预示着大模型推理成本可能迎来新一轮的下降。正如评论中所言，这种进步是架构创新与规模化效应共同作用的结果，而开源这些核心组件将极大推动长上下文应用的发展。
