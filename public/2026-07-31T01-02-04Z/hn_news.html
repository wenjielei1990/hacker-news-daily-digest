Agent Skill to Force Docs in ASD-STE100 Simplified Technical English HN 讨论 · 66

SimpleEnglish 是一个为大语言模型（LLM）设计的“智能体技能”工具，旨在强制模型使用 ASD-STE100 简明技术英语标准编写文档。该标准最初于 1983 年为航空航天业开发，通过严格的词汇和语法规则（如每句不超过 20 词、禁用被动语态）来消除歧义。该工具能有效解决 AI 生成内容中常见的冗长、含糊和“领英风格”的废话。测试显示，应用该技能后，文档的 STE 违规率降低了约 73%，且输出的 Token 数量也显著减少。虽然它能极大提升技术文档的清晰度，但其输出风格机械扁平，并不适合营销或品牌文案。

展开详情 ↓

ASD-STE100 是一种受控语言标准，其核心逻辑是“一个词对应一个含义”，最初是为了确保疲惫的飞机维修人员不会误读指令而设计的。在 LLM 时代，模型往往倾向于生成充满修饰词和被动语态的“AI 废话”（Slop），而 SimpleEnglish 通过将这一航空级标准转化为系统提示词或智能体技能，迫使模型回归到极简、务实的写作风格。该工具涵盖了 53 条具体规则，包括限制句子长度、强制使用简单时态、禁止使用“-ing”形式的动词，以及要求先陈述条件再给出指令。这种风格不仅提高了文档的可读性，还因为减少了冗余 Token 而降低了推理成本。

在对多个 Claude 模型进行的 96 次压力测试中，所有模型的表现均有显著提升，平均句子长度从 11.2 词降至 9.7 词。这种“波音手册”风格对于故障排除、运行手册和发布说明等技术场景非常理想，因为它将“清晰”从一种主观感受变成了一套可测试的规范。然而，这种方法也有明显的局限性：它的语调完全剥离了品牌个性和文学色彩，显得非常机械。此外，虽然该工具能显著减少违规，但由于 ASD 官方并不认证任何自动化工具，生成的文档在严苛环境下仍需人工审核以确保完全合规。

Stacked PRs are now live on GitHub HN 讨论 · 159

GitHub 宣布“堆叠拉取请求”（Stacked PRs）功能正式进入公开预览阶段，旨在解决大型代码变更难以评审的问题。该功能允许开发者将一个复杂的任务拆分为一系列有依赖关系的、小而集中的 PR，形成一个逻辑上的“堆叠”。评审者可以并行处理这些小 PR，而开发者无需等待前一个 PR 合并即可继续后续开发。系统提供了一键合并整个堆叠的功能，并集成了命令行工具 `gh stack` 来简化分支管理。目前该功能在处理“压缩合并”模式和分支同步方面仍存在一些已知限制，尚处于完善阶段。

展开详情 ↓

GitHub 推出的堆叠 PR 功能主要针对现代开发中 PR 规模过大、评审周期过长的痛点。通过将复杂的变更分层，每一层都成为一个独立的 PR 并指向其下方的变更，开发者可以构建起清晰的逻辑链条。这种方式不仅让评审者能专注于更小的代码增量，还允许团队成员并行评审不同的层级，从而缩短反馈循环。GitHub 在 Web 界面中增加了“堆叠地图”导航，方便用户直观查看各 PR 之间的依赖关系，并支持在满足条件时一键合并整个堆叠或部分层级。

为了支持这一工作流，GitHub 发布了 `gh stack` 命令行扩展，帮助开发者在本地快速创建和管理堆叠。然而，早期用户反馈在“压缩合并”（squash merge）模式下存在挑战：由于压缩合并会改变提交历史，导致上层 PR 往往需要重新获得评审批准，这在一定程度上抵消了效率提升。此外，一些资深开发者指出，GitHub 的实现依然基于“多分支”模型，而非像 Gerrit 或 Phabricator 那样基于“提交修订”模型。这意味着开发者仍需手动处理大量分支的变基（rebase）和同步，对于追求极致简洁工作流的团队来说，这可能只是一个折中方案。

Google DeepMind 发布了 Gemini Robotics 2，这是一套旨在赋予机器人“全身智能”的新型模型。该系统包含负责将视觉和语言转化为动作的 VLA 模型，以及用于复杂任务规划和多机协作的推理模型。其核心突破在于实现了从足尖到指尖的全身协调控制，并能让模型在几小时内快速适配全新的机器人硬件。尽管展示了清理房间和协作等复杂任务，但目前机器人动作仍显迟缓。这一进展标志着机器人正从预设程序的自动化向具备自主学习和环境适应能力的智能化转变。

Gemini Robotics 2 由三个核心模型组成：主 VLA 模型负责将多模态输入直接转化为电机控制指令，支持人形机器人的行走、下蹲及精细的手部操作；ER 2 推理模型则充当“大脑”，负责理解人类指令、感知物理世界并进行长达数分钟的多步骤任务规划；此外还有一个优化的端侧模型，支持在本地运行并实现跨硬件的快速迁移。DeepMind 强调了“跨体现”（cross-embodiment）能力，即软件可以迅速适应不同形态的机器人身体，解决了以往机器人开发中软硬件高度耦合的痛点。在演示中，机器人展示了团队协作清理杂乱房间的能力，这要求极高的环境理解和动态路径规划。然而，技术挑战依然显著：大型模型带来的推理延迟可能影响实时反应速度，且现有的机械执行器在动作流畅度上仍远逊于生物。未来的观察重点在于，这种基于大模型的“端到端”控制能否在保持智能的同时，突破物理执行的频率和精度瓶颈。

每一个时代都有其独特的设计语言，AI 时代也不例外。目前，“星星”表情符号（✨）已成为 AI 功能的通用代号，而流式文本和闪烁动画则被用来暗示机器正在“思考”。在视觉上，AI 应用倾向于使用极小的图标、米色背景和衬线字体，这与传统的操作系统原生风格形成了鲜明对比。这种美学部分源于 AI 的不确定性，导致界面经常出现动态重排的“打地鼠”现象。虽然这些元素正在向普通软件渗透，但它们究竟是持久的范式转移还是短暂的流行，仍有待观察。

文章探讨了 AI 浪潮如何催生出一套全新的设计美学。最显著的标志是 ✨ 表情符号，它从代表魔法或庆典转变为 AI 的专属图标。在交互层面，为了适应 AI 生成内容的延迟，流式输出和模拟“思考”状态的文本闪烁效果变得随处可见，并开始被非 AI 软件借用来表示异步任务。作者还观察到，像 Claude 和 Cursor 这样的 AI 应用偏爱极细小的图标和米色调的复古配色，这在 macOS 等原生系统中显得格格不入。

Prized 是一款面向非工程师员工的 AI 内部工具构建平台，允许用户通过自然语言描述需求来生成全栈应用。它解决了运营、财务等部门因排期问题无法获得工程支持的痛点，能将零散的表格或脚本转化为连接公司数据的正式工具。为了保障安全，该平台在网络层对 AI 沙箱进行隔离，并通过代理服务器管理敏感凭据，避免密钥泄露。此外，所有外部 API 调用都会经过 LLM 裁判的实时审计以防止危险操作。尽管降低了开发门槛，但如何确保 AI 生成逻辑的长期可靠性仍是其面临的主要挑战。

Prized 旨在填补 Lovable 等原型生成工具与 Retool 等专业低代码平台之间的空白。它让非技术员工只需描述功能，即可获得一个集成公司单点登录（SSO）并连接生产数据的完整应用。该系统的核心优势在于其安全架构：沙箱环境从不接触真实的 API 密钥，而是使用不透明的占位符，仅在请求通过出口代理时才由系统替换为真实凭据。这种设计配合默认拒绝的网络策略，极大地降低了数据外泄的风险。对于外部连接器的调用，Prized 引入了 LLM 裁判机制来拦截潜在的破坏性指令。

在协作方面，Prized 采用了类似 GitHub 的模式，允许员工查看、分叉（fork）并改进同事创建的工具，从而在公司内部形成可复用的工具库。例如，数据科学家可以将包含硬编码阈值的脚本转化为带有 UI 控件的风险控制台，供全公司使用。每个工具都运行在独立的数据库架构和角色下，并配有完整的审计日志以满足合规需求。未来，Prized 需要在赋予员工构建自由的同时，进一步完善管理员对复杂数据流的精细化管控，并应对来自通用大模型（如 Claude）原生集成能力的竞争。
