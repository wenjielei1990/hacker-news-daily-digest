电梯调度比看起来复杂得多，其核心在于平衡等待时间和运行效率。最基础的 LOOK 算法只在有请求的方向移动，而更先进的 RSR 算法则通过评分系统每 5 秒重新优化一次派梯方案。虽然 RSR 考虑了负载和反聚堆等因素，但在高流量或小建筑中，简单的 LOOK 反而表现更好。令人意外的是，预选楼层的“目的层调度”系统在减少等待时间上往往不如传统按钮，因为它牺牲了重新分配电梯的灵活性。人们对电梯的感知通常取决于最长的那次等待（p90），而非平均时间。

这篇文章深入探讨了支撑现代建筑运行的电梯调度算法。最简单的 SCAN 算法像扫描仪一样在顶层和底层间往返，而目前最普及的 LOOK 算法则更聪明，它只在有请求的情况下才继续向上或向下运行。在多部电梯协作的场景中，奥的斯开发的 RSR（相对系统响应）算法引入了复杂的评分机制。该机制会综合考虑预计到达时间、当前负载、反聚堆惩罚以及空闲奖励，并且每隔 5 秒就会根据实时路况重新计算最优派梯方案。然而，模拟数据显示，在极端高峰期或电梯数量较少的建筑中，简单的 LOOK 算法往往比复杂的 RSR 更稳健。

文章还揭示了一个反直觉的结论：现代写字楼流行的“目的层调度”系统（即在梯厅先选楼层）在大多数情况下其实比传统的上下按钮更慢。虽然这种系统能获取更多信息，但它强制乘客进入指定电梯，导致系统失去了在乘客等待期间根据新状况重新分配电梯的灵活性。此外，电梯性能的衡量标准通常是 p90 等待时间，因为乘客往往会忽略平均等待时间，而对那 10% 极慢的等待体验记忆深刻。未来的调度优化不仅要考虑算法逻辑，还需应对早高峰、午餐时段等截然不同的流量模式，以及如何在算法效率与机械磨损之间取得平衡。

qm 是一个专为初创团队设计的开源 AI 智能体（Agent）协作框架，支持在 Slack 和 Web 端同步运行。与常见的个人 AI 助手不同，它为每位成员提供隔离的沙箱环境、内存和权限体系，同时允许在共享频道中进行多用户协作。该框架兼容 Claude Code 和 OpenCode 等多种底层驱动，能处理文档搜索、邮件分选、代码 PR 提交及 CI 监控等复杂任务。其核心机制依赖 Postgres 进行会话持久化，并提供从“严格审批”到“自动执行”的三种安全模式。目前该项目对社区贡献有特殊要求，仅接受人类编写的自然语言提案，而非 AI 生成的代码。

展开详情 ↓

qm 试图解决当前 AI 智能体大多局限于“个人助手”而难以融入团队工作流的问题。它采用了一种“多玩家”架构，核心是一个基于 Node.js 和 Postgres 的无头后端，能够调度不同的 AI 驱动程序（如 Pi 或 Claude Code）。每个用户或协作空间都拥有独立的持久化沙箱，这意味着安装的工具和环境变量在不同会话间是持续存在的。这种设计让 AI 不再只是一个聊天窗口，而是一个拥有公司内部权限、能操作数据库并监控系统日志的“虚拟员工”。

在安全性方面，qm 引入了预声明的命令策略，即使在最宽松的“危险模式”下，也会拦截破坏性的 SQL 或递归删除操作。值得关注的是其“反洗稿（Anti-slop）”设计理念，例如内置了专门的审美技能，强制避开 AI 常见的模板化设计风格。尽管功能强大，但 qm 的部署和维护具有一定门槛，它要求企业在自己的云账户中运行。此外，项目维护者对 AI 生成内容的警惕性极高，甚至在贡献指南中明确禁止使用 AI 扩充提案，这种“用 AI 开发却排斥 AI 贡献”的策略在社区中引发了不小的讨论。

Progressive Web Components HN 讨论 · 17

资深设计系统架构师 Ariel Salminen 推出了轻量级库 Elena，旨在通过“渐进式 Web 组件”理念解决原生 Web 组件在 SSR 支持、布局偏移和过度依赖 JavaScript 等方面的顽疾。该方法提倡 HTML 和 CSS 优先的架构，将组件分为基础渲染层和 JS 增强层，确保在脚本加载前页面即可用。这种模式能显著提升首屏性能并改善 SEO，同时保持了 Web 组件跨框架的通用性。然而，其核心挑战在于开发者在构建复杂交互时，是否能坚持这种“渐进增强”的约束而非重回 JS 驱动的老路。

展开详情 ↓

Elena 是一个仅 2.6kB 的微型库，专门为构建企业级设计系统而设计。它提出了“渐进式 Web 组件”（PWC）的概念，将组件划分为复合型、原始型和声明型三种模式，允许开发者根据需求在 Light DOM 或 Shadow DOM 之间灵活切换。与 Lit 等重度依赖 JS 运行时的库不同，Elena 强调“水合”而非完全由客户端渲染，从而有效避免了未样式内容闪烁（FOUC）和布局偏移。它内置了属性与特性的同步、事件委托以及响应式状态管理，且完全基于 Web 标准，不产生任何运行时依赖。

在技术实现上，Elena 支持声明式 Shadow DOM，这使得组件在保持样式隔离的同时也能实现顺滑的服务器端渲染（SSR）。对于不含 render() 方法的组件，它们天然兼容任何后端环境；而对于复杂组件，Elena 提供了可选的 SSR 工具链。这种架构的优势在于极高的可移植性，一套组件库可以无缝运行在 React、Vue 或纯 HTML 环境中。不过，这种“回归原始”的开发方式也存在权衡：开发者需要承担更多的架构设计责任，以确保 HTML 结构在失去 JS 支持时依然语义正确且具备基本功能，这在处理高度动态的 UI 时可能比使用现代框架更具挑战性。
