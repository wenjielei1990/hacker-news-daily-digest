Qwen 3.8 27B HN 讨论 · 571

阿里巴巴发布了 Qwen 3.8-27B 开源模型，这是一款拥有 270 亿参数的稠密模型，原生支持视觉语言理解。该模型引入了默认开启的“思考模式”，通过显式的推理过程来处理复杂的编程和智能体任务。在 SWE-bench Pro 和 DeepSWE 等多项基准测试中，它的表现超越了 Claude Opus 等顶级闭源模型。它支持最高 100 万 token 的超长上下文，并针对长视频理解进行了优化。然而，深度推理也带来了显著的计算开销，部分用户反映其在本地运行时存在推理时间过长和显存占用较高的问题。

展开详情 ↓

Qwen 3.8-27B 是通义千问系列的最新迭代，采用了基于 Qwen 3.5 的架构改进，并引入了多标记预测（MTP）技术。该模型最大的特色是其“灵活思考控制”机制，允许用户通过 reasoning_effort 参数调节推理深度，并在对话中保留历史推理上下文。在技术规格上，它拥有 64 层网络，支持原生 262k 上下文并可通过 YaRN 技术扩展至 100 万 token。官方评测显示，它在处理代码修复、自动化终端操作和长程办公任务（CoWorkBench）方面表现卓越，甚至在某些指标上优于参数量大得多的闭源旗舰模型。

尽管性能强劲，Qwen 3.8-27B 在实际部署中也面临效率挑战。由于其默认开启深度推理，生成响应前可能需要消耗数千甚至数万个推理 token，导致在普通硬件上的等待时间显著增加。社区测试发现，该模型在处理长上下文时的显存占用（KV Cache）比 Gemma 4 等模型更高，这限制了它在显存有限的设备上处理超长任务的能力。此外，有用户观察到其推理风格呈现出一种类似“原始人笔记”的简略特征，且在某些量化版本下可能出现逻辑循环。未来，社区更期待看到基于此架构的混合专家模型（MoE）版本，以期在推理速度和模型能力之间达成更好的平衡。

RISC-V: They should have known better HN 讨论 · 51

这篇文章深入批评了 RISC-V 指令集架构在设计上的诸多缺陷，认为它试图同时兼顾低端微控制器和高性能服务器的需求，结果在两端都表现不佳。在微控制器领域，RISC-V 的中断处理延迟远高于竞争对手 ARM，且压缩指令的设计限制过多，影响了代码密度。在高性能计算领域，它缺乏高效的寻址模式，导致处理数组等常见操作时指令冗余。最严重的问题是“可选性”泛滥，几乎所有核心功能都是可选的，这导致了严重的生态碎片化。作者指出，甚至连检测硬件功能的机制本身也是可选的，这给软件开发者带来了巨大麻烦。

展开详情 ↓

作者 Dmitry 认为 RISC-V 试图成为一种“万能”架构是一个根本性错误，因为微控制器和高性能 CPU 的设计目标往往是互斥的。在低端嵌入式场景中，RISC-V 的中断响应速度很慢，因为它需要通过软件手动保存大量寄存器，而竞争对手如 Cortex-M0 则通过硬件自动处理，效率更高。此外，它的压缩指令集设计得非常古怪，例如某些存储指令的偏移量范围极小，限制了实际的代码压缩效果。

在高性能领域，RISC-V 缺乏像 x86 或 ARM 那样的复杂寻址模式，处理简单的数组访问往往需要三条指令。虽然支持者寄希望于“指令融合”技术来弥补，但作者认为这在实际硬件实现中非常困难且低效。更糟糕的是，RISC-V 的标准过于松散，乘除法、特权模式甚至计时器都是可选的。这种极度的可选性导致开发者无法确定硬件到底支持什么功能，甚至连查询硬件能力的寄存器（misa）本身也是可选的，且在用户模式下往往无法访问。作者总结道，在 2020 年还犯下这些几十年前就已解决的设计错误，反映了设计委员会在脱离现实地进行“精神自慰”。

随着微软 Edge 浏览器跟随谷歌 Chrome 的脚步转向 Manifest V3 扩展标准，Firefox 成为目前唯一完整支持 uBlock Origin 的主流浏览器。谷歌推动的这一技术迁移限制了扩展程序拦截网络请求的能力，导致原版 uBlock Origin 在 Chromium 系浏览器上无法正常运行。虽然这些浏览器提供了功能受限的“精简版”插件或内置拦截器，但其灵活性远不如原版。Firefox 凭借其独立的 Gecko 引擎，依然保留了对旧版 API 的支持。这使得 Firefox 在广告拦截和隐私保护方面再次获得了显著的竞争优势，但也凸显了现代 Web 生态对单一引擎的过度依赖。

展开详情 ↓

谷歌在 Chromium 引擎中强制推行 Manifest V3 标准，核心变动是用限制更多的 declarativeNetRequest API 取代了原有的 webRequest API。这一变动虽然打着提升性能和安全的旗号，但实际上剥夺了广告拦截插件实时拦截和修改网络请求的权力。由于 Edge、Brave 和 Opera 等主流浏览器均基于 Chromium 开发，它们不得不逐步放弃对原版 uBlock Origin 的支持。用户在这些平台上只能选择功能缩水的 uBlock Origin Lite，或者依赖浏览器自带的拦截功能，后者往往缺乏高级过滤规则和动态拦截能力。

相比之下，Firefox 作为非 Chromium 系的代表，通过其 Gecko 引擎继续提供对 Manifest V2 的支持，确保了 uBlock Origin 的完整功能。Firefox 甚至将该插件列入“推荐扩展”名单，由官方人员对其每次更新的代码进行人工审计，以确保没有恶意代码。这种架构上的独立性让 Firefox 在隐私发烧友眼中成为了最后的堡垒。然而，这种优势也伴随着隐忧：Firefox 的大部分收入仍来自谷歌的搜索协议，这种微妙的利益制衡决定了它很难像 Brave 那样直接将强力广告拦截功能内置到浏览器核心中。未来，用户可能需要在“更安全的 API 限制”与“更强大的用户控制权”之间做出最终选择。

Eigendrum 将复杂的物理数学问题带入了浏览器，让用户直观感受几何形状与声音之间的联系。它模拟的是边缘固定的鼓膜振动，其核心是求解拉普拉斯算子的特征值问题。由于大多数不规则形状没有解析解，该工具采用了数值计算方法：先将用户绘制的形状进行三角网格化，然后构建有限元刚度和质量矩阵，最后解出代表振动频率的特征值。为了保证准确性，开发者针对圆（贝塞尔函数）和矩形等已知精确解的形状进行了严格测试，误差控制在 0.1% 以内。
