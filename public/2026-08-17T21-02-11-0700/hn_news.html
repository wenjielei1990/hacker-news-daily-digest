How Bluesky draws its logo on screenshots HN 讨论 · 220

社交平台 Bluesky 在用户截图时会巧妙地在图片中植入其 Logo，而该 Logo 在平时使用时并不可见。其技术原理是利用了 iOS 系统为保护密码等敏感信息设计的“安全文本输入”机制。Bluesky 将“关注”按钮放置在这一特殊图层中，当系统检测到截图动作时会自动隐藏该图层，从而露出预先藏在下方的 Logo。这种做法虽然在技术上很聪明，但因滥用隐私保护接口进行品牌推广而引发了争议。目前苹果尚未对此类 API 的非安全用途做出限制。

展开详情 ↓

本文揭秘了 Bluesky 移动端应用如何在截图瞬间完成“变脸”：用户在应用内看到的“关注”按钮，在截图中会变成蓝色的蝴蝶 Logo。作者通过查阅 Bluesky 的开源代码发现，这一功能被直白地命名为“增长黑客（GrowthHack.tsx）”。它利用了 iOS 的 `isSecureTextEntry` 属性，该属性原本是为密码输入框设计的，旨在防止敏感信息在截图或录屏中泄露。当 iOS 执行截图操作时，会自动将此类安全图层抹除，而 Bluesky 恰好将 Logo 渲染在按钮正下方的底层，从而实现了这种“隐形水印”效果。

这种技术手段在开发者圈内并非秘密，Telegram 和 Signal 等应用也曾利用类似机制来保护私密聊天内容。然而，Bluesky 将其用于营销目的引发了广泛讨论。在相关的 GitHub 代码提交记录中，不少开发者对其表示反感，导致讨论帖最终被锁定。这种做法的争议点在于，它破坏了用户对“所见即所得”截图体验的预期，将原本用于保护用户隐私的工具转变为服务于厂商利益的广告手段。目前，这种行为在 iOS 平台上仍处于监管灰色地带。

在20世纪90年代中期，CD-ROM的640MB容量远超当时PC硬盘和游戏资源的需求。id Software为了利用剩余空间，将《毁灭战士》和《雷神之锤》完整版等加密文件塞进了共享版光盘。这种模式旨在让玩家通过拨打1-800电话支付费用并换取解锁码，从而实现即时购买。然而，黑客组织GNOMON很快发现，所谓的解锁码并非由服务器动态生成，而是由本地程序FLOW.EXE根据随机挑战码计算得出的。这意味着整个保护机制仅仅依赖于“通过模糊实现安全”，没有任何真正的密钥交换。

DuckDB 2.0（代号 Cyanoptera）计划于今年秋季发布，是该分析型数据库自发布以来最重要的版本更新。核心变化是引入了“服务器模式”，通过 Quack 扩展和 CONNECT 语句，DuckDB 不再局限于单进程嵌入式使用。新版本全面支持触发器（Triggers）和增强的 VARIANT 类型，后者能像处理列式数据一样高效处理 JSON。底层引入了异步 I/O 机制，大幅提升了从 S3 等远程对象存储读取数据的并行度和速度。此外，全新的 SQL 解析器和稳定的 C API 为扩展生态提供了更好的兼容性和灵活性。尽管功能大幅增强，但默认存储格式的升级意味着用户在迁移旧数据时需要进行格式转换。

传统的语音 AI 代理通常由 STT、LLM 和 TTS 三个环节串联而成。由于每个环节都有数十家供应商且模型更新极快，开发者往往在选定一套方案后就很难再进行优化，导致生产环境长期运行在过时且昂贵的模型上。Speko 通过将这一评估和集成过程 API 化，允许开发者根据特定语言、地区和性能指标（如词错率或响应延迟）实时路由到最佳供应商。其核心优势在于自动化的基准测试，涵盖了自发语音、医疗词汇和长达十分钟的通话等复杂场景，帮助开发者在不同语境下找到最匹配的模型组合。

How do functions like alloca allocate memory from the stack? HN 讨论 · 14

alloca 函数允许程序在运行时从栈中动态分配内存，其核心机制是直接调整栈指针。为了防止分配的内存过大而跳过操作系统的“保护页”，编译器会插入对 __chkstk 函数的调用。这个辅助函数会按顺序“探测”每一页内存，确保操作系统能及时捕捉到栈增长的需求并分配物理内存。这种机制与编译器处理大型局部变量的方式完全一致，确保了内存访问的安全性。虽然现代编程中 alloca 因容易导致栈溢出而较少使用，但它展示了底层软件与硬件协作的精妙之处。

展开详情 ↓

在 C 和 C++ 编程中，局部变量通常在编译时就确定了大小，但 alloca 函数提供了一种在运行时从栈上动态划出空间的方法。在 Windows 等现代操作系统中，栈内存并非预先全部分配，而是通过一个名为“保护页”（guard page）的机制按需扩展。如果程序一次性跳过太大的空间去访问内存，可能会越过保护页，导致操作系统无法识别这是合法的栈增长，从而引发崩溃。为了解决这个问题，alloca 在调整栈指针（RSP）之前，必须调用编译器提供的 __chkstk 函数。该函数的作用是以 4KB 为步长依次触碰每一页内存，从而触发操作系统的缺页中断，确保栈空间被正确物理化。Raymond Chen 通过 x86-64 汇编代码展示了这一过程：函数在进入时会为固定大小的局部变量调用一次 __chkstk，随后在执行 alloca 时会根据动态计算的大小再次调用。这种设计保证了即使是动态的栈分配也能与系统的内存管理机制无缝衔接。尽管如此，开发者仍需警惕 alloca 可能引发的栈溢出风险，因为它不像堆分配那样可以返回空指针来表示失败。

scScript 是一款专为 Linux 设计的类 C 脚本语言，旨在将 C 的熟悉语法与脚本语言的便利性相结合。它编译为高效字节码并在自定义虚拟机上运行，支持协程、闭包和自动内存管理。该语言的一大特色是去除了指针操作，并引入了独特的“输入/输出”双变长参数机制。项目还集成了一个名为 scEmacs 的轻量级编辑器，用于代码编写和交互。目前该工具仅支持 64 位 Linux 环境，适合追求 C 语言风格但需要脚本灵活性的开发者。

展开详情 ↓

scScript 被其作者描述为一封“写给 C 语言的情书”，它在保留 C 风格语法和操作符的同时，通过移除复杂的指针管理降低了开发门槛。该语言支持 64 位数值运算、不可变 UTF-8 字符串以及自动扩容的数组和字典。其独特之处在于提供了“进（in）”和“出（out）”两组变长参数列表，这种设计旨在比传统的返回多个值或使用指针的方式更优雅地处理函数输出。在底层，scScript 实现了栈式异步协程、尾递归优化，并采用标记清除与引用计数混合的垃圾回收机制。

为了提供完整的开发体验，项目集成了 scEmacs 编辑器，支持多窗口、颜色显示和基本的文本编辑功能。scScript 的代码库完全由 C 语言编写，依赖极少（仅 libx11、libxft 和 libffi），这使得它非常容易被嵌入到其他应用中。尽管目前它局限于 64 位 Linux 平台，但其提供的从源代码到抽象语法树（AST）再到字节码的全透明编译过程，为开发者提供了极高的控制力。未来值得关注的是该语言在嵌入式系统或作为特定领域语言（DSL）方面的应用潜力。
