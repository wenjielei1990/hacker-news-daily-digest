“I just chose words carefully” HN 讨论 · 100

在 20 世纪 90 年代末，一位名为 rs1n 的作者编写了一份《超级银河战士》游戏攻略，其排版方式令人惊叹。这份长达 1.7 万字的文章在等宽字体下实现了完美的左右对齐，且没有使用任何双空格或连字符。作者并非依靠自动化工具，而是通过精心挑选和改写词汇，使每一行文字都恰好填满预设的宽度。这种做法解决了等宽字体在两端对齐时空格过大或分布不均的视觉问题，但也意味着极大的创作工作量。虽然这种“人肉排版”在现代数字写作中极为罕见，但它体现了对文本视觉呈现的极致追求。

展开详情 ↓

在等宽字体（monospace）中实现文本的两端对齐一直是个难题。通常的自动对齐会导致空格过大且分布不均，产生难看的视觉“空洞”，而使用连字符又会破坏文本的连贯性并干扰复制粘贴。然而，rs1n 在其经典的《超级银河战士》攻略中采取了一种极端的解决方案：通过重写文本来适配行宽。这意味着他必须不断调整用词，确保每一行的最后一个字符都精准地落在右边界上，从而在不添加额外空格的情况下实现完美的矩形排版。

这种工作量是巨大的，整份攻略超过 1.7 万字，每一行都像是一块经过精密计算的拼图。作者在 FAQ 中淡然表示，他没有使用任何程序，只是在 ASCII 编辑器中“仔细挑选了词汇”。这种对排版的痴迷不仅是为了美观，也解决了一个技术限制下的美学难题。在现代，虽然我们拥有复杂的排版引擎，但这种精神在 UI 开发中依然存在。例如，开发者为了让按钮或提示信息在有限的像素宽度内不被截断，往往需要反复推敲文案。这种对文字与空间关系的极致掌控，是数字时代早期一种独特的“工匠精神”，展示了人类在受限环境下迸发的创造力。

Linux 内核官网 git.kernel.org 正面临 AI 爬虫的疯狂冲击，这些爬虫舍弃高效的 git clone 方式，转而通过渲染 HTML 页面来抓取提交记录。为了规避封锁，爬虫利用嵌入智能电视等设备的住宅代理 SDK 发起攻击，导致网站 20% 的 CPU 算力被浪费在无效渲染上。尽管运维方部署了 Anubis 工作量证明（PoW）系统，但随着爬虫算力提升，PoW 难度已增加到令手机用户感到发烫的程度。目前合法请求仅占流量的 2%，迫使官方不得不考虑削减匿名访问的功能。这一现象凸显了 AI 训练对互联网公共资源造成的沉重负担。

展开详情 ↓

Linux 内核维护者 Konstantin Ryabitsev 揭示了 git.kernel.org 遭受 AI 爬虫侵蚀的现状。由于内核代码是高质量且无 AI 污染的训练素材，各大模型实验室正不计成本地抓取。令人费解的是，这些爬虫并未采用最高效的 git clone 协议，而是选择逐个渲染 HTML 提交页面，这导致服务器 90 个核心中有 14-16 个常年处于满载渲染状态。爬虫通过集成在智能电视和移动应用中的“代理 SDK”隐藏身份，利用数百万个住宅 IP 发起零星请求，使传统的 IP 封禁手段彻底失效。

为了反击，官方引入了 Anubis 系统，要求访问者完成 SHA256 计算挑战。起初效果显著，但爬虫很快进化，迫使 PoW 难度不断升级。现在的难度已导致移动端用户需等待数秒且设备明显发烫，严重损害了真实开发者的体验。目前，尽管 66% 的请求被拦截，仍有 33% 的爬虫成功解题。运维团队表示，如果 AI 泡沫不破裂或爬虫不改变抓取策略，他们将不得不限制匿名访问功能，甚至关闭部分高耗能的 Web 界面，这标志着开放互联网资源在 AI 掠夺式抓取面前正被迫走向封闭。

开源操作系统 Haiku 发布了 R1/beta6 版本，此时正值该项目成立 25 周年。作为 BeOS 的精神续作，Haiku 坚持“纯粹桌面”定位，不含现代系统的广告、遥测或强制云服务。本次更新改进了驱动支持和系统稳定性，但部分用户在特定硬件上遇到了启动回归问题。尽管它在视觉和响应速度上独具特色，但缺乏无障碍支持和现代容器化功能仍是其主要短板。对于追求简洁工具感和复古体验的用户来说，它依然是一个独特的避风港。

展开详情 ↓

在距离上一个测试版发布两年后，Haiku 团队推出了 R1/beta6。Haiku 的核心魅力在于其完全为桌面端设计的架构，避免了 Linux 那种“服务器优先”带来的复杂性，也没有 Windows 或 macOS 中常见的服务化倾向。新版本在 USB 音频和硬件兼容性上有所提升，但社区反馈显示，在某些 ThinkPad 设备上出现了 ACPI 相关的启动故障，需要通过安全模式禁用相关功能才能进入系统。此外，虽然现代浏览器的移植提升了实用性，但 Haiku 在无障碍技术（Accessibility）上的缺失依然是一个巨大的挑战，因为这类堆栈的实现极其复杂且充满各种“黑科技”补丁。

目前社区中一个显著的争议点是 Haiku 对 AI 生成代码的严厉禁令。官方为了保证代码质量和版权纯洁性，拒绝接受 AI 编写的补丁，这导致一些由 AI 辅助开发的驱动程序（如 Focusrite 声卡驱动）或 PowerPC 架构的分支只能在主干之外独立存在。与此同时，随着 Linux 在性能优化和容器化技术上的快速迭代，一些老用户发现 Haiku 在旧硬件上的速度优势已不再明显。未来 Haiku 需要在保持其独特的“工具感”与追赶现代硬件标准、提升开发效率之间找到微妙的平衡。

Zig 的 std.ArrayList 是一种动态数组，当其容量不足以容纳新元素时会触发内存重新分配，这会导致之前获取的所有指向数组元素的指针或切片失效。为了降低此类内存安全风险，Zig 借鉴了之前在 HashMap 中引入的经验，为 ArrayList 增加了指针稳定性锁。开发者在获取元素指针前调用 lockPointers()，在指针失效后调用 unlockPointers()。这种机制通过在容器内部维护状态，确保在锁定期间任何可能改变内存布局的操作（如 append、resize 甚至是不涉及分配但会移动元素的 orderedRemove）都会触发断言失败。

Storyteller 平台最近重构了其核心的“强制对齐”（Forced Alignment）算法，旨在解决电子书文本与有声书音频同步中的复杂难题。传统的对齐方法在面对章节顺序错乱（如前言被移至音频末尾）、内容缺失（如音频跳过附录）或用词微调时往往会失效。作者引入了一种基于 n-gram 和 RANSAC 的边界搜索算法，能够在大规模音频中快速定位文本章节的粗略位置。随后，通过 Massively Multilingual Speech (MMS) 模型生成的 CTC 发射数据，结合 Viterbi 动态规划算法，将对齐精度提升到了单词级别。

这种技术方案相比直接使用 Whisper 等转录模型具有显著优势：它不仅支持超过 1000 种语言，还能提供更精确的时间戳，从而实现平滑的单词级高亮显示。在实现过程中，算法通过寻找全局唯一的“锚点”将长章节拆分为小段处理，极大地提高了计算效率。尽管单词级高亮在视觉上非常吸引人，但开发者也意识到这可能对某些读者的视线移动造成干扰，因此在 UI 设计上保留了句子级高亮的选项。未来，该项目计划进一步优化多语言支持，并探索如何更好地处理电子书与音频之间的文本差异。
