AX – Google’s Open Agentic Orchestrator HN 讨论 · 113

Google 推出了开源智能体编排器 AX，旨在解决传统微服务架构在处理 AI 智能体时的高昂成本和低效问题。智能体的工作负载通常具有突发性和长时运行的特点，在等待模型响应或人类审批时，传统的闲置沙箱会浪费大量资源。AX 通过声明式控制平面实现了亚秒级的挂起与恢复，并提供了基于微虚拟机的安全隔离环境。它将任务、工作空间和网络策略抽象为核心原语，支持大规模智能体集群的运行。然而，用户对 Google 长期维护开源项目的信誉表示担忧，且该项目与现有生态的集成度仍有待观察。

展开详情 ↓

AX 是由 Google DeepMind 研究成果转化而来的开源项目，专门为“智能体即参与者”（Agent-as-Actor）这一新计算范式设计。传统的编排器（如 Kubernetes）主要针对无状态微服务或可预测的批处理任务，而智能体往往需要长时间保持状态，但在等待 LLM 响应、工具反馈或人类干预时又处于空闲。AX 解决了这一痛点，它支持极速的状态挂起与恢复，避免了为闲置沙箱支付高昂的计算费用。该系统底层重度依赖 Agent Substrate，利用微虚拟机（MicroVMs）或 gVisor 提供强隔离环境，确保运行不可信代码时的安全性。

在功能上，AX 提供了零信任网络策略，允许开发者精确限制智能体访问的域名和端口（例如仅限 Git 仓库或特定的 LLM 接口）。它还引入了任务、工作空间和模型的声明式管理，简化了大规模智能体集群的部署。尽管技术指标亮眼，但社区讨论中也暴露出一些挑战：AX 被认为是一个“绿地”项目，其独立性较强，可能不如 Google 的另一个项目 Scion 那样容易与现有工具集成。此外，开发者们对 Google 频繁关停项目的历史心存芥蒂，担心 AX 是否能获得长期的官方支持，以及它是否真的能成为企业级智能体运行的标准方案。

三星电子正加速布局高端存储市场，预计明年 HBM4 和 HBM4E 的产量将大幅增长。行业消息显示，三星已将玻璃载板的月外包清洗量从今年的 2 万片提升至明年的 5 万片。玻璃载板在 HBM 制造中至关重要，它在晶圆减薄和钻孔过程中起到支撑作用，防止多层堆叠时发生弯曲或破裂。随着堆叠层数增加到 12 层及以上，这种物理支撑技术的精度直接决定了良率。

ChatGPT now knows what you do on other websites via ad collector HN 讨论 · 352

OpenAI 正在通过一种名为 __obi 的追踪 Cookie，将用户的 ChatGPT 账户与其在其他网站上的浏览行为关联起来。这种机制类似于 Meta 和 Google 的广告追踪像素：当用户访问安装了 OpenAI 追踪代码的第三方网站时，浏览器会自动发送该 Cookie。收集的数据包括用户搜索的产品、阅读的文章以及购买行为，甚至能抓取经过哈希处理的邮箱和电话。关键在于，OpenAI 将此 Cookie 归类为“分析”而非“营销”，这意味着拒绝营销追踪的用户可能仍被监控。目前该机制在 Chrome 等支持第三方 Cookie 的浏览器上有效，但在 Safari 或 iOS 浏览器上受限。

展开详情 ↓

调查发现，OpenAI 的广告平台（内部代号 Bazaar）利用 bzr.openai.com 域名设置了一个名为 __obi 的持久性 Cookie。当用户登录 ChatGPT 时，系统会生成一个包含账户 ID 的令牌并将其绑定到该 Cookie 中。由于该 Cookie 被配置为 SameSite=None，它专门用于跨站请求。这意味着，只要第三方网站安装了 OpenAI 的广告衡量像素（Pixel），用户访问这些网站时的详细行为——如浏览路径、地理位置甚至部分表单数据——都会被发送回 OpenAI，并与其 ChatGPT 身份匹配。

追踪代码不仅收集 URL，还会主动抓取页面上的身份信息。虽然邮箱和电话经过了 SHA-256 哈希处理，但邮编、城市等地理信息则是明文传输。研究显示，即使是未登录的匿名用户，OpenAI 也会分配一个长达 27 天的稳定标识符进行追踪。值得注意的是，OpenAI 在其政策中将 __obi 归类为“分析”类 Cookie。这导致了一个潜在的合规漏洞：即便用户在隐私设置中拒绝了“营销”类追踪，只要勾选了“分析”选项，该追踪机制依然会运行。目前，由于苹果 Safari 的智能追踪预防（ITP）机制，该手段在 iOS 设备上失效，但在安卓版 Chrome 上已被证实有效。

Pirate Face Rescues LLM Models from Deletion HN 讨论 · 139

Pirate Face 是一个为开源 AI 模型提供去中心化存储的 P2P 平台，旨在防止模型因中心化托管方删除而消失。它利用 BitTorrent 协议将 Hugging Face 上的模型转化为种子，并使用“Web 种子”技术在模型未删除时直接从官方服务器提速。所有文件均通过 SHA-256 校验和与 Hugging Face 官方记录比对，以确保模型权重未被篡改。这一举措主要针对被标记为“经消融（abliterated）”的去中心化或非审查模型，为其提供永久生存空间。目前该平台仍高度依赖 Hugging Face 进行初始发布和身份验证，且模型的长期存续取决于社区的做种意愿。

展开详情 ↓

Pirate Face 试图通过引入 BitTorrent 协议，解决开源 AI 社区对 Hugging Face 等中心化平台可能实施审查或意外删除模型的担忧。其核心机制是 BEP-19 规范中的“Web 种子（web-seed）”：在模型尚存于 Hugging Face 时，用户通过种子下载实际上是直接从官方 HTTPS 链接拉取数据；一旦官方链接失效，下载将自动切换到 P2P 群集，即所谓的“救援（Rescued）”状态。为了解决镜像站点常见的安全信任问题，Pirate Face 强制要求每个文件必须匹配 Hugging Face 官方的 SHA-256 校验和，确保用户下载的是原始权重而非植入后门的版本。

该平台目前支持 MIT 和 Apache-2.0 等开源协议的模型，并对特定的非审查模型（如 Kimi-K3 的消融版）提供支持。用户无需注册即可下载或做种，但通过关联 Hugging Face 账号可以获得创作者认证，防止身份冒用。尽管其愿景是实现“主权 AI”，但目前的局限性显而易见：提交新模型仍需先上传至 Hugging Face 以获取校验基准，且如果某个冷门模型在被官方删除后没有足够的社区节点持续做种，它依然会从互联网上消失。未来，该项目计划支持直接发布功能，以彻底摆脱对中心化平台的依赖，并提供兼容 Hugging Face 的 API 切换接口。
